Ucebul Workspace API

Documentación de Endpoints

Esta documentación describe los endpoints actuales del módulo Workspace expuestos bajo el prefijo /api. Incluye autenticación con Sanctum, reglas de acceso, payloads esperados y la forma real de las respuestas según los controladores implementados.

Base URL /api Auth Authorization: Bearer {token} Formato JSON Roles admin / super_admin

Navegación

Autorización

Nivel Descripción
Público No requiere token.
Auth Requiere auth:sanctum.
Admin Requiere rol global admin o super_admin.
Super Admin Exclusivo para super_admin.

Notas importantes

  • Todas las rutas de esta página usan el prefijo real /api.
  • Los endpoints protegidos requieren el header Authorization: Bearer {token}.
  • Los show, update y destroy devuelven 404 si el registro no existe.
  • El endpoint forgot-password devuelve el OTP en la respuesta para el MVP actual.
  • Los permisos de aplicación pueden estar asociados a módulos; si no tienen módulo quedan bajo without_module.

Permisos agrupados por módulo

Cuando un endpoint devuelve permisos organizados, usa el module_slug como clave estable para frontend.

{
  "permissions": {
    "users": {
      "module_name": "Usuarios",
      "module_slug": "users",
      "permissions": [
        {
          "workspace_application_permission_id": 1,
          "workspace_application_permission_name": "Ver usuarios",
          "workspace_application_permission_slug": "users.view"
        }
      ]
    },
    "without_module": {
      "module_name": "Sin módulo",
      "module_slug": null,
      "permissions": []
    }
  }
}

Auth

POST /api/auth/login Público

Autentica un WorkspaceUser por email y contraseña y genera un token Sanctum.

Body

{
  "workspace_user_email": "admin@workspace.com",
  "workspace_user_password": "secret123",
  "workspace_personal_access_token_name": "optional_token_name"
}

Respuesta 200

{
  "success": true,
  "message": "Login successful",
  "data": {
    "workspace_user": {
      "workspace_user_id": 1,
      "workspace_user_email": "admin@workspace.com",
      "workspace_user_name": "Admin",
      "workspace_user_last_name": "Root",
      "user_roles": [...],
      "user_applications": [...]
    },
    "workspace_access_token": "1|plain-text-token",
    "workspace_access_token_type": "Bearer"
  },
  "meta": []
}
Errores comunes: 422 por validación, 401 por credenciales inválidas.

}

Respuesta 200

{
  "success": true,
  "message": "OTP generated successfully",
  "data": {
    "workspace_otp": {
      "workspace_otp_id": 12,
      "workspace_otp_email": "admin@workspace.com",
      "workspace_otp_code": "654321",
      "workspace_otp_purpose": "password_reset",
      "workspace_otp_expires_at": "..."
    },
    "workspace_user": {
      "workspace_user_id": 1,
      "workspace_user_email": "admin@workspace.com"
    }
  },
  "meta": []
}
Actualmente expone el OTP generado en la respuesta para facilitar pruebas del MVP.
POST /api/auth/verify-otp Público

Valida un OTP por email, código y propósito. Solo acepta OTP no usado y no expirado.

Body

{
  "workspace_otp_email": "admin@workspace.com",
  "workspace_otp_code": "654321",
  "workspace_otp_purpose": "password_reset"
}

Respuesta 200

{
  "success": true,
  "message": "OTP is valid",
  "data": {
    "is_valid": true,
    "workspace_otp": {
      "workspace_otp_id": 12,
      "workspace_otp_email": "admin@workspace.com",
      "workspace_otp_code": "654321"
    }
  },
  "meta": []
}

  "workspace_otp_code": "654321",
  "workspace_user_password": "new-password-123",
  "workspace_otp_purpose": "password_reset"
}

Respuesta 200

{

  "message": "Password reset successfully",
  "data": {
    "workspace_user": {
      "workspace_user_id": 1,
      "workspace_user_email": "admin@workspace.com"
